# 情景选股建议：开发与复测说明

日期：2026-10-27。适用代码：`Iaster/system`。本次为本地开发与验证，尚未部署到测试或生产服务器。

## 测试反馈与原因

测试人员发现牛市、熊市、平衡市返回相同股票。原拟持仓接口将股票库按代码排序，在三个股票 Sleeve 内分别固定选取前两只成长股和前两只价值股，每只组内权重25%。该逻辑没有读取市场情景或个股行情。

初始股票库包含24只证券：美股、日本、新兴市场各8只，并支持管理员收录组织专属证券。推荐每组4只不代表数据库只有4只。线上实际数量应以该组织股票库为准。

## 新行为

在“拟投资组合”点击“按当前情景生成建议”，系统从已确认 Sleeve 目标关联的年度数据包读取情景，检查本组织已启用证券的行情，生成独立预览。查看评分和权重后，点击“载入系统建议”才会替换未保存草稿。提交、回测与审批流程仍然适用；涉及锁定持仓的改动不允许载入。

选股范围是本组织股票库，并非自动搜索全球上市股票。新增证券通过管理员收录流程核验后即可进入下一次筛选，不需要修改推荐代码。

| 情景 | 年化收益评分权重 | 26周动量 | 较低年化波动 | 较小最大回撤 | 成长/价值目标 |
| --- | --- | --- | --- | --- | --- |
| 牛市 | 45% | 30% | 15% | 10% | 60% / 40% |
| 平衡市 | 30% | 10% | 30% | 30% | 50% / 50% |
| 熊市 | 10% | 0% | 45% | 45% | 40% / 60% |

模型版本为 `scenario-stock-screen-v1`。上述规则属于新增、明确披露的启发式筛选方法，尚未完成真实行情投资效果验收，不能把推荐状态当作回测通过。不同情景允许选中相同股票；分数、风格占比与个股权重由相应规则计算，不为制造差异强行换股。

## 数据及限制

- 复用现有 EODHD / Yahoo 行情源及后备源规则，最多3个并行行情请求，总时限90秒。
- 使用最多157个完整周的调整价格，剔除当前未结束周和未来价格。每只至少100个完整周，最新价格距生成时间不超过21天。
- 同一 Sleeve 在共同周区间上评分。几何年化收益按实际日历周跨度计算；年化波动使用对数价格变动及每段实际周长估计（漂移为累计对数收益/累计周长，方差为各段漂移残差平方/段长之和，再除以样本段数减一，按52周年化）；最大回撤沿真实价格计算。近26周动量取26周起点或之前最近共同周，详情显示实际跨度，长假可能为27周。缺失周不填充，也不会把长假跨度当成一周。
- 同一 Sleeve、同一风格内部按指标百分位评分。并列指标得分相同，综合分相同按代码及证券ID稳定排序。
- 遵守本档案参数快照的获准市场、每种风格最少/最多只数和单股上限。必要时增加股票数量；风格目标占比按可用容量调整。每个 Sleeve 权重精确合计100%，保留8位小数。
- 缺失、历史不足、过期、市场未获准等证券显示排除原因。任一 Sleeve 无法形成合规候选时，不返回部分组合，也不退回固定股票清单。
- 预览展示股票库数量、可评分数量、入选数量、指标、得分、建议权重、价格区间与来源。每次完成的推荐将目标版本、年度数据包、参数、评分、结果和覆盖报告写入审计。
- 筛选没有针对目标 Beta 做组合优化，也没有约束新兴市场内部港股/A股比例；正式回测继续按已确认目标和基准检验，必要时进入原有优化流程。

## 验证及复测

自动测试包括情景差异、允许相同入选名单、排序稳定性、风格数量、单股上限、非对称候选池、权重精度、缺失/过期/短历史、长假缺周、日历动量及未来价格、角色权限、组织隔离、目标关联和审计记录，以及已批准持仓不变。API集成测试使用内存 PostgreSQL 兼容数据库和模拟行情，不请求真实数据服务。

本地浏览器已检查牛市、熊市、平衡市生成预览、载入未保存草稿、行情不可用时禁用载入，以及390px iframe视口的响应式布局。浏览器采用隔离组件与合成价格，不连接投资账户或业务数据库。

验证结果：API 122项、Web 19项、Domain 21项，合计162项自动测试通过；三个包的类型检查和生产构建通过。构建与测试使用当前锁定依赖版本，未修改依赖清单或锁文件。

测试人员复测步骤：

1. 使用相同组织和股票库，准备三个已确认至拟投资组合步骤的情景档案。
2. 逐个点击“按当前情景生成建议”，检查情景名称、股票库数量、评分规则与行情区间。
3. 展开详情核对入选与未入选股票的分数、指标和建议权重；允许名单重叠。
4. 载入建议，核对各 Sleeve 权重100%、数量与单股限制；确认此时仍为未保存草稿。
5. 提交并运行正式回测，记录未通过的 Beta、收益、回撤约束，必要时进入优化和审批。
6. 对行情失败或候选不足档案，确认有明确原因且不能载入空组合；历史批准版本保持不变。

本次无需新增数据库迁移或重置数据。部署时需同时更新 API 和 Web 构建；真实数据源连接及三情景业务验收尚待部署后复测。
